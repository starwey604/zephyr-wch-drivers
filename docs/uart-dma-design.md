# UART DMA: round 1 contract and lower-layer audit

## Status and scope

Update: the [out-of-tree DMA prerequisite](dma-driver.md) now addresses the
upstream DMA findings below. This document preserves the round-1 audit;
UART async TX/RX still have not been implemented.

Round 1 adds validation and a testable arithmetic boundary, NOT asynchronous
transfers. `WCH_UART_DMA_PREPARE` checks DMA resources but neither starts nor
reserves channels. `SERIAL_SUPPORT_ASYNC` is deliberately not selected; there
are no successful stub implementations of the async UART API.

The first transfer implementation will target CH32V203 USART1/2, default pin
mapping, 8N1, no RTS/CTS, byte-wide non-cyclic DMA and static per-device state.
No heap, USB, PM, wide data, hardware half-duplex or other WCH series in this
stage. Runtime baud configuration is not implemented; use DT `current-speed`
and rebuild for now. Unsupported framing fails initialization with `-ENOTSUP`.
The old import's parity path was not a validated 8-bit-plus-parity implementation
and is now rejected rather than silently selecting an incorrect word length.

The release lacks the `exti` node referenced by Gello's DTS. An unmodified
Gello build on v4.4.0 fails at devicetree parsing, before compiling UART code.
The release also lacks CH32V203's DMA1 DT node, despite having the DMA driver.
Use `bluepillplus_ch32v203` with the committed UART test overlay, which adds
DMA1 and routes both USARTs, to isolate driver/API compatibility. This is NOT
proof that the full Gello board works
on the release. Keep Ragtime's Zephyr pin unchanged; backporting board/EXTI
support would be a separate task.

`src/api_contract.c` in the UART test checks the callback, TX, abort, RX,
buffer-response, disable and DMA config/status signatures against the actual
headers. Public signatures used here agree across the baselines. The newer
DMA inline wrappers use `DEVICE_API_GET`; do not access private Zephyr driver
tables or assume the entire API/header is byte-identical.

## Initialization and resource ownership

- `WCH_UART` remains opt-in and mutually exclusive with upstream
  `UART_WCH_USART`; CMake rejects the duplicate driver configuration.
- Check framing, clock device readiness, clock-enable result, clock-rate result,
  valid BRR range and pinctrl result before enabling USART. The baud helper
  uses 64-bit intermediate arithmetic and does not change outputs on error.
- With DMA preparation enabled, DMA must initialize before UART. Check both
  controllers are ready; reject missing/disabled controllers and bad mappings
  at build time. No DMA request is generated by these checks.
- USART1 uses DMA1 indices TX=3/RX=4; USART2 TX=6/RX=5. The hardware manual
  numbers channels starting at 1, while the Zephyr driver starts at 0.
- These checks do not allocate channels or protect against a different driver
  claiming them. Stage 2 must resolve exclusive fixed-channel ownership before
  enabling requests. The pinned upstream WCH DMA driver has no channel filter:
  `dma_request_channel()` chooses a free channel, not necessarily the fixed
  hardware request. Do not pass a desired channel and assume it is honored.
  Use an explicit static ownership policy, or separately implement and test
  fixed-channel filtering; never manipulate another driver's private bitmap.
  The external `WCH_DMA` replacement now implements this filter using a
  `uint32_t *` zero-based channel index and is enabled in the preparation tests.
- Applications own buffer storage; driver ownership is a temporary loan.
  During a loan, applications must not modify TX or recycle RX memory.

## Planned per-port state (not implemented in round 1)

TX and RX have independent state so they can run simultaneously. Each port
will hold its own callback/user data, DMA configurations/block descriptors,
generation counters and timeout work. DMA descriptors must outlive transfers;
no stack-local descriptors retained by asynchronous code.

| Direction | States | Completion boundary |
| --- | --- | --- |
| TX | IDLE, STARTING, DMA_ACTIVE, WAIT_UART_TC, STOPPING | DMA completion moves to WAIT_UART_TC; UART TC ends the transfer |
| RX | DISABLED, STARTING, ACTIVE, STOPPING | Report remaining bytes, release current/queued buffers, then disable |

TX stores immutable buffer pointer, length and progress. Exactly one terminal
event may be emitted for an accepted transfer: DONE or ABORTED. Validate and
claim state before hardware setup; setup failure returns an error and restores
IDLE without emitting a terminal event for an unaccepted operation. Precise
aborted-byte accounting must distinguish DMA progress from bytes on the wire.

RX stores current buffer/length, last reported offset, optional next buffer,
timeout setting and progress snapshot. A next buffer may be supplied from a
callback. Empty progress emits no RX_RDY event. Every accepted buffer is
released once; RX_DISABLED is last. During STOPPING, new starts remain busy;
the final disabled callback may immediately start a fresh reception. With no
next buffer, report and stop; never overwrite a buffer already returned to
the application. Timeout/disable/IRQ paths must share one accounting mechanism.

## Locking and event delivery rules for implementation

1. Serialize thread calls, UART IRQ, DMA callbacks and timeout work with a
   per-device spinlock around short state/register transitions. No blocking
   operations in critical sections; audit DMA calls for their lock behavior.
2. Snapshot event data and callback under the lock; invoke application code
   after releasing it. Callback reentry is expected, especially RX buffer
   responses and starting a new operation after terminal notification.
3. Revalidate state/generation after callbacks. A generation counter alone
   cannot distinguish a stale hardware interrupt: disable requests, quiesce
   DMA and clear relevant peripheral/pending flags before channel reuse.
4. Delayed work must check that it still belongs to the current operation.
   Cancellation/restart must not let an old timeout stop a new transfer.
5. RX DMA writes continue independently of CPU locks. Establish a stable
   progress snapshot and appropriate memory ordering before delivering data;
   do not assume masking CPU interrupts freezes the DMA engine.
6. Interrupt-driven and async callbacks must not drive the same UART together.
   Preserve Zephyr's exclusive-callback rules when async is added. Polling
   RX must not steal async RX data; polling TX must not interleave with DMA TX.
7. No logging, allocation or unbounded application processing on transfer hot
   paths. Counters and captured event traces belong in tests/diagnostics.

## Lower-layer audit and decisions

Sources: pinned `drivers/dma/dma_wch.c`, `drivers/clock_control/clock_control_wch_rcc.c`
and `hal_wch/ch32fun/ch32v20xhw.h`. No core or HAL files are patched in round 1.

| Finding | Consequence / decision |
| --- | --- |
| DMA supports single-block byte transfers and remaining count via `dma_get_status()` | Start with normal DMA and fixed peripheral/incrementing memory addresses |
| DMA CNTR mask is 16 bits; driver maximum uses `(2 << 16) - 1` | Bound our byte transfers to 1..65535; reject oversized requests before calling DMA |
| Completion ISR disables the channel even with CIRC configured | Do not rely on cyclic operation; a separate DMA fix and tests are required before using it |
| Callback selects TC before TE when both are present | Simultaneous completion/error handling needs review before robust error qualification |
| Half-transfer is reported as `DMA_STATUS_BLOCK` | Do not confuse that with final completion or blindly assume HALF_COMPLETE semantics |
| `dma_stop()` disables EN but does not itself clear all pending flags | Audit quiesce/reconfigure ordering before accepting restart/abort guarantees |
| No DMA `chan_filter` implementation | Generic allocation does not guarantee the required fixed request channel |
| 4.4.99 fixes base/extended channel boundary comparisons | USART1/2 use indices 3..6; do not generalize this port to DMA2/other channels |

The first helpers only validate length and compute non-cyclic RX deltas; they
do not verify RAM accessibility, hardware DMA completion or interrupt races.
At 3 Mbaud 8N1, a byte takes about 3.33 us. Software DMA rearming may leave a
gap. Decide direct double-buffer versus internal circular staging from measured
latency, CPU load and Gello's 20 KiB RAM budget in the continuous-RX stage.

## Next increment

Implement TX callback registration, fixed DMA channel ownership/configuration,
`uart_tx()` and `uart_tx_abort()`, followed by UART TC completion. Keep RX
unsupported until its implementation lands. Add tests for failure rollback,
busy state, cancellation and exactly-once terminal notification. Do not mark
the device as providing a complete production async implementation during
partial bring-up; document the supported subset and keep it explicitly opt-in.
